# M8: Page tools

Status: **in progress** (2026-10-14), branch `m8` (cut from `cleanup-cli`).
One commit per slice; notes per slice at the end.

## Decided at kickoff (2026-10-14)

**Generated pages are files.** Every source in the document model is a
PDF on disk. Save, incremental save, recovery and the renderer all reopen
it by path. Pages made from images and blank pages are therefore written
as small PDFs to a content-addressed cache directory
(`<cache>/sheaf/generated/<hash>.pdf`) and added as ordinary sources. Being
content-addressed, a file survives a crash, so recovery can still find it,
and the same image inserted twice is one file. Nothing deletes them yet;
they're small, and a cache cleanup can come later.

**Operations go in `sheaf-ops` when the command line needs them**, as in
the ops/CLI plan: combine and split (both get subcommands). Insert, crop,
labels and stamps are document edits in `sheaf-doc`, which the GUI drives.

**Combine Files writes a file and opens it.** Acrobat makes an untitled
document. sheaf documents are files, so Combine asks where to save first,
as File > Create > From Scans/Photos does.

**Headers, footers, Bates numbers, watermarks and backgrounds are "stamps":**
- **In the model,** a document-level list of definitions, each applied to
  a set of pages. Undo and redo cover them.
- **On screen,** they're drawn over the page until saved, like sheaf's
  marks.
- **At save,** they're baked into page content as marked-content artifacts
  the way Acrobat writes them (`/Artifact <</Type /Pagination /Subtype
  /Header>> BDC … EMC`, plus the page's `/PieceInfo /ADBE_CompoundType`).
  Acrobat can then update or remove them, and so can we: Remove strips
  those blocks from the content of files written by either app.

**Crop is per-page state** (a CropBox in the page's own space), written as
`/CropBox` at save. How the view honours it is settled in its slice, after
looking at the page-geometry code.

**Page labels become editable state.** A document-level list of ranges,
anchored to page ids so they survive reorders, written as `/PageLabels`.
Today a rewrite drops the file's labels after any reorder; with the
ranges in the model, they're kept.

## Slices

1. **Combine Files.**
   - The op is `sheaf_ops::combine`: PDFs and images, each with an
     optional page range, an optional bookmark per file (with each PDF's
     own bookmarks nested under it), and images at their own size or
     fitted to Letter/A4.
   - The CLI is `sheaf combine -o out.pdf a.pdf:1-3 scan.tif b.png`.
   - The GUI is File > Create > Combine Files…: a list that can add files,
     add a folder, or take dropped files; reorder and remove; a page range
     per file; the options; then Create (save, then open).
   - The generated-file cache lands here.
2. **Split.**
   - The op `sheaf_ops::split` splits every N pages, by ranges, by
     top-level bookmark, or by maximum file size.
   - The CLI is `sheaf split`, and the GUI Document > Split Document….
   - Splitting the open document includes its unsaved edits.
3. **Insert blank page, insert from images, Replace Pages.** These go in a
   Document > Insert Pages submenu (From File…, From Image…, Blank Page…),
   plus Replace Pages….
4. **Crop pages.**
   - Document > Crop Pages… takes margins or "trim white margins", applied
     to the current, selected, all, or a range of pages.
   - The view, thumbnails, print and export all show the crop, and it's
     saved as `/CropBox`.
5. **Page labels.** Document > Page Labels… sets the style, prefix and
   start for a range. They're shown in the status bar and thumbnails, and
   written as `/PageLabels`.
6. **Headers/footers and Bates numbering.**
   - The text can include the page number, page count, date and file name.
   - Six positions, font size, colour and margins; applied to a range of
     pages.
   - Add, update and remove.
   - Bates gets prefix, suffix, zero padding and a start number.
7. **Watermarks and backgrounds.**
   - Text or image, with opacity, rotation, position and scale.
   - In front of or behind the page content.
   - Add, update and remove.
8. **Bookmark extras.**
   - Create bookmarks from a page range (one per page, titled by label or
     number).
   - Colorize bookmarks by level.
   - Bookmark every match of a pattern, from the Patterns panel.

## Slice notes
1. Done. The pieces:
   - `sheaf_doc::generated` (the cache, plus `blank_pdf` for slice 3).
   - `sheaf_ops::open::describe`, which reads a file's `SourceInfo` and
     bookmarks.
   - `sheaf_ops::combine` and `sheaf combine`.
   - File > Create > Combine Files… (`combine_dialog.rs`, with its own
     icon).

   The op builds a document from the first file and adds the rest as
   sources, a contiguous run of pages at a time. Then it rewrites the
   result. Bookmarks to pages left out are dropped unless something under
   them stays (they become headings). sheaf's own marks in the inputs are
   carried over; a plain rewrite would strip them from non-primary pages.

   Deviations: the dialog is a list with a page-range field per file. The
   roadmap's thumbnail grid for choosing pages is left for later.
   `file:range` on the command line splits at the last colon only when the
   whole argument isn't an existing file, so Windows drive letters work.
   Checked by a CLI test (pages, order, nested and flat bookmarks) and a GUI
   run that picked a folder of two PDFs and a JPEG.
2. Done. `sheaf_ops::split` and `sheaf split` split every N pages, by
   ranges, by top-level bookmark, or by maximum size. Document > Split
   Document… (`split_dialog.rs`) splits the open document, unsaved edits
   included, and shows how many files it will make.
   - **Bookmark splits.** Each part is named `<stem>_<title>` (made safe
     for file names; a repeat gets `_2`). Pages before the first bookmark
     become `<stem>_Start`.
   - **Size splits.** Each part takes as many pages as fit, found by
     doubling then bisecting with `save::extract_bytes`, an in-memory
     extract added here. A page too big alone becomes its own part, with a
     warning.
   - **Background jobs.** Export and Split now share `jobs.rs`, which runs
     a `sheaf_ops` op on a background thread, shows it in the status bar
     and progress strip, and stops it on Esc. The export-only code moved
     there.
   - **Naming.** `sheaf_ops` re-exports the progress snapshot as
     `ProgressSnapshot`, so it can't be confused with the document's.

   Checked by a CLI test (count, ranges, and sizes each at most the limit)
   and a GUI run splitting the Combine output at its three bookmarks.
3. Done. There's now a Document > Insert Pages submenu (From File…, From
   Images…, Blank Pages…) and Replace Pages…:
   - **Blank Pages.** The current page's size or Letter/A4/Legal, how
     many, and where (after or before the current page, the start, or the
     end).
   - **From Images.** Fitted to one of those sizes (portrait; a landscape
     image turns its page) or at the image's own size.
   - **Both** become a PDF in the generated cache and go in through
     `insert_file`, the general form of Insert PDF.
   - **Replace Pages** picks a PDF, then takes two ranges: pages of this
     document, and one run of the file's. It uses the model's existing
     `ReplacePages`, so replaced pages keep their ids, and with them their
     bookmarks and comments.

   Checked in the GUI by inserting 2 blank pages (9 → 11), an image (12),
   and replacing page 1 with another file's page 1.
4. Done. Document > Crop Pages… (`crop_dialog.rs`) takes margins (in, mm
   or pt, as the page is shown) or trims white margins (render at 72 dpi,
   find the ink, keep 9 pt), on the current, selected, all or a range of
   pages.

   How it works (the decision the kickoff left open):
   - **A cropped copy.** `sheaf_ops::crop::plan` writes the affected
     source pages to a generated PDF with a new `/CropBox`
     (`save::cropped_copy`; sheaf's own marks are left out, the model
     keeps them).
   - **A new edit.** `Edit::RebasePages` moves the document's pages onto
     that copy, keeping ids, rotation and bookmarks, and shifting marks
     and OCR text by the crop offset (`AnnotKind::translated`, moved here
     from the app, and `TextLayer::shifted`).
   - **Why.** PDFium renders, sizes and maps text for the cropped page by
     itself, so none of the view's page-size code had to learn about
     crops. Save, print, export and undo all work unchanged.

   Bugs found and fixed on the way:
   - **Geometry used the MediaBox.** sheaf's page geometry (`PageGeom`,
     `PageFrame`; save, file reading and the renderer's bookmark frames)
     used the MediaBox, while PDFium shows the CropBox. Marks on files
     that already had a CropBox were misplaced. All three now use the
     visible box (CropBox clipped to MediaBox), with a test.
   - **Stale images.** The view's image caches are keyed by page id, so a
     page that changed what it shows kept its old image. That hit Replace
     Pages (slice 3), and undoing it, too. `Doc::touched` now drops cached
     images of pages whose source page changed.

   Not done: bookmark destinations with positions (`/XYZ`) on cropped
   pages aren't shifted.

   Checked by integration tests (the margin crop moves the mark, the
   saved `/CropBox` is right, undo works, trim finds a 100 pt square) and
   a GUI trim plus undo.
5. Done. Page labels live in the model, `DocState::labels`, as
   `LabelSpec`s anchored to the page id each range starts at.
   - **Loading.** The file's ranges are read into the model on open
     (`set_initial_labels`, in the app and in `sheaf_ops::open`).
     `FileFacts` now carries the ranges, not the label strings.
   - **The edit.** `Edit::SetPageLabels` replaces them.
     `labels::apply` does what Acrobat's dialog does: number a run, and the
     page after it keeps the label it had, so numbering past the change
     is unchanged.
   - **Saving.** The rewrite and the incremental save both write
     `/PageLabels` from the model (a `labels_dirty` flag, like the
     outline's). Labels now survive reorders instead of being dropped. A
     document whose labels were never read keeps the old rule: keep the
     file's unless pages moved.
   - **Display.** Status bar, thumbnails and Go to Page read the model,
     cached per document version.
   - **Extracts.** They carry the labels of their pages; a range whose
     start page isn't in the part goes, and the part starts with plain
     numbers.

   Checked by unit tests (apply, reorder, the number tree) and a save
   round trip by both strategies, plus a GUI run (page 1 → "i", saved
   incrementally as `/Nums [0 <</S /r>> 1 <</S /D /St 2>>]`).
